GOOD QUESTIONS / 06

A few things
worth knowing.

What the idea is designed to do—and where it keeps its limits visible.

Is Codebase Whisperer available now?

This page presents the product concept and proposed workflow. The project is being built; capabilities shown here are design previews, not claims about a live service.

How does it keep answers grounded?

It retrieves repository evidence, asks for claims tied to that evidence, and checks citation paths and line ranges before displaying them. These checks improve traceability but cannot prove every interpretation is correct.

What happens if the repository does not contain an answer?

The intended behavior is to say that there is not enough evidence and show where it searched, rather than inventing a path or a confident explanation.

Can it make changes to GitHub on its own?

No. The design separates proposals from execution. A person reviews the exact issue or pull request content and approves it before a separate handler performs the action and reads the result back.

Does it keep up with repository changes?

The planned approach refreshes an index against newer commits and reprocesses changed files. It should be described as refresh-based synchronization, not real-time tracking.

Which repositories and languages will it support?

The first build is scoped to one public GitHub repository and selected languages supported by its parsers. Broader repository and language coverage is a later extension.

Action approvals

Prepare an issue, generate a code fix, or open a draft pull request. Review the exact diff and destination, then approve before any GitHub write.

The agent uses indexed code to draft a small patch, then runs detected checks in Docker with networking disabled when Docker is available. Review the diff and results; no GitHub write happens until you approve.

Preparing a proposal does not contact GitHub.
